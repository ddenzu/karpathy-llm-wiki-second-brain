이 볼트를 `karpathy-llm-wiki-second-brain` 템플릿의 최신 상태로 갱신한다.

## 절대 원칙

**사용자 소유 파일은 절대 덮어쓰지 않는다** — `index.md` · `log.md` · `wiki/` · `raw/`.
이 경로는 아래 어떤 단계에서도 `git checkout` 대상에 넣지 않는다.

## 1. 템플릿 원격 연결 (최초 1회, 멱등)

```bash
git remote get-url template >/dev/null 2>&1 || \
  git remote add template https://github.com/ddenzu/karpathy-llm-wiki-second-brain.git
git fetch template
```

⚠️ 이 볼트가 git 저장소가 아니면 여기서 멈추고, 레포에서 `skills/`·`.claude/commands/`를 직접 내려받으라고 안내한다.

## 2. 템플릿 소유 경로를 통째로 갱신

`git pull`은 쓰지 않는다 — 템플릿으로 만든 저장소는 히스토리가 달라 거부되거나 사용자 노트와 충돌한다.
**경로만 꺼내오는 방식**이라 머지가 아니고 충돌이 없다.

```bash
git checkout template/main -- .claude/commands/ skills/
```

- 이 커맨드 파일 자신도 여기서 갱신된다(의도된 것 — 다음 실행부터 최신 규칙이 적용됨).
- 템플릿에 새 경로가 생기면 **위 목록에 추가한 새 버전이 이 단계에서 내려오므로**, 사용자는 다음 실행에서 자동으로 받는다.

## 3. `CLAUDE.md`는 병합한다 (덮어쓰지 않는다)

스키마는 템플릿 것이지만 사용자가 반드시 고치는 부분이 있다(언어 줄, 자기 규칙).
**그래서 이 파일만은 기계적으로 덮지 말고 네가 읽고 판단해서 병합한다.**

```bash
git diff HEAD template/main -- CLAUDE.md
```

diff를 읽고:
- **템플릿이 새로 추가·수정한 규칙** → 사용자 파일에 반영한다.
- **사용자가 고친 부분**(언어 설정, 추가한 자기 규칙, 경로 커스터마이즈) → **그대로 보존한다.**
- 어느 쪽인지 애매하면 **묻는다.** 임의로 정하지 않는다.
- 규칙의 **위치가 의미를 갖는 경우**(예: 특정 절 바로 밑에 붙어야 충돌이 해소되는 단서)는 위치까지 맞춘다.

## 4. `README.md`

개인 볼트에서는 안 쓰는 문서다. **기본은 건드리지 않는다.** 사용자가 원하면 그때 갱신한다.

## 5. 보고

무엇이 바뀌었는지 인라인으로 보고한다:
- 새로 들어온 파일 / 갱신된 파일 (`git status --short`)
- `CLAUDE.md`에 반영한 규칙과 보존한 사용자 수정
- **스킬을 받았다면**: `skills/` 는 볼트 안에 있을 뿐 아직 동작하지 않는다 —
  `~/.claude/skills/` 로 복사하고 각 `SKILL.md` 의 `{{VAULT_PATH}}` 를 이 볼트의 절대경로로
  바꿔야 한다고 안내한다.
- 커밋은 **하지 않는다.** 워킹트리에 두고 사용자가 확인 후 정한다.

## 6. 로그

의미 있는 변경이 있었으면 `log.md` 맨 끝에 한 줄 append 한다(기존 줄 수정 금지):
`## [YYYY-MM-DD] update | 템플릿 동기화 — <바뀐 것 요약>`
